# MacGacha: guide for AI agents

Read this before you change anything. **Keep it current:** when you add a module, a script, a user-visible feature or a new rule, update the matching section in the same PR.

## What this is

MacGacha is a native macOS launcher for Genshin Impact, Honkai: Star Rail and Zenless Zone Zero on Apple Silicon, for Global servers and, in beta, Mainland China.

- **What it does:**
  - installs, updates, verifies and repairs games through HoYoverse's official Sophon delivery;
  - manages Wine, DXMT and D3DMetal runtimes side by side;
  - launches each game with a verified per-game recipe.
- **Requirements:** macOS 27, Apple Silicon. SwiftUI, Swift 6 language mode, strict concurrency.
- **License:** GPL-3.0-only, with an extra term under section 7(b): keep the link to the original project. See `NOTICE`.

The README's Roadmap section is the user-facing status. Update it when a feature lands.

## Build and test

```bash
scripts/bootstrap.sh          # generate MacGacha.xcodeproj from project.yml (needs xcodegen)
scripts/test.sh               # everything CI runs locally: headers, package tests, app tests, string catalog check, Release build
swift test --package-path Packages/LauncherKit --filter <Suite>   # one package suite
```

- **Run `scripts/test.sh` with `MACGACHA_DERIVED_DATA_PATH` pointing outside `~/Documents`**, for example `MACGACHA_DERIVED_DATA_PATH=/tmp/macgacha-dd scripts/test.sh`. Derived data inside `~/Documents` triggers a macOS privacy (TCC) prompt that hangs the test runner.
- CI (`.github/workflows/ci.yml`) runs three parallel jobs (package tests, app tests and string catalog, Release build). The package job also runs the `DownloadEngineTests` with one cooperative thread (`LIBDISPATCH_COOPERATIVE_POOL_STRICT=1`). Run that step locally when you touch concurrency:
  ```bash
  LIBDISPATCH_COOPERATIVE_POOL_STRICT=1 python3 scripts/test-package.py --events /tmp/strict.jsonl --timeout-seconds 240 --skip-build --test-product DownloadEngineTests --skip PlanScaleTests --skip operationStagesOneThousandBatchesWithLinearWork --parallel --num-workers 2
  ```
  Never block a cooperative thread: no semaphores, sleeps or synchronous waits in async code. Use `BlockingIO.run` for blocking syscalls.
- The gated live Wine inspector probe runs only with `MACGACHA_LIVE_WINE=/absolute/path/to/wine`; it explicitly initializes an isolated temporary prefix with `wineboot --init`, polls the inspector for rewritten `cmd.exe` on a bounded clock deadline, then shuts down that prefix and reaps its direct child.
- `LaunchIntegrationTests` is gated on `MACGACHA_RUNTIME_FIXTURES`. It installs the pinned Wine 11.20/D3DMetal and Wine 11.0/DXMT bundles from local archives, then launches a D3D11 probe through the real manager, prefix preparation, proxy and logs. It SIGKILLs `CrashHarness` at hide/restore journal and rename boundaries, reattaches while Wine is live, and verifies conflict recovery through the next launch. All state lives in temporary roots. Every manager runs in a deadline-controlled `CrashHarness` child; cancellation cancels and joins that bounded child runner. Teardown runs in an uncancelled task with deadlines for `wineserver -k`/`-w`, checks both exit codes (Wine 11's empty-output `-k` status 1 additionally requires an idle pinned-prefix server namespace), and requires an empty successful prefix-scoped inspector scan before removing the pinned temporary root. Shutdown failures or inspection uncertainty retain the root and fail the test. `withProbeTestRoot` owns setup as well as execution: a failed/cancelled partial extraction is removed in an uncancelled task, while an unexpected prefix retains the root. `ProbeTeardownTests` covers partial setup, cancellation and deadline failures without Wine; the gated matrix also forces persistent live inspection failure and proves bounded exit and subsequent recovery. Package-only recipe overrides and file hooks select the test recipe and exact crash boundaries; shipped recipes remain the default.
  - The local fixtures also need `d3d11waitprobe.c` / `d3d11waitprobe.exe`: the C wrapper calls the original `d3d11probe.c`, flushes stdout, creates `probe-ready` in its working directory, and waits for `probe-release` with a bounded deadline. Build locally with `x86_64-w64-mingw32-gcc -O2 -o d3d11waitprobe.exe d3d11waitprobe.c -ld3d11 -ldxgi -ldxguid`. Never commit fixture binaries. Tests wait for file events and manager running confirmation before releasing the probe; readiness deadlines name the bundle, harness mode/checkpoint and signal, and include the durable child phase, signal states and last inspection error; elapsed time is only a failure bound. `TestSupport/LaunchIntegrationSupport.swift` shares the temporary configuration with the crash child. `ProbeTestLifetime.swift` owns the bounded child lifecycle and checked teardown; the harness's `cleanup` mode retries teardown for a retained root.
- Debug screenshots can combine `-MacGachaDebugRegion cn` with `-MacGachaDebugGameState playing` (or `launching`, `launchFailed`, `recoveryNeeded`, `progress`, `verifying`, `installingSlow`, `downloadStalled`, `busy`, `ready`); fake states and recovery notices belong to the visible region.
- `BackdropVideoTests` include synthetic WebM parser fixtures, a generated 128x128 decode fixture (some hardware rejects 64x48 sessions), hidden/superframe decoding and bounded multi-loop tests. Native codec tests skip if VP9 hardware decoding is not advertised after supplemental registration. `MACGACHA_BACKDROP_VIDEO=/absolute/cached/file.webm swift test --package-path Packages/LauncherKit --filter 'NativeLayerTests|VP9DecoderTests'` opts into a real-file decode and native-layer readiness check without copying the asset.
- The build must have **zero Swift warnings**.
- `scripts/check-headers.sh`: every Swift file starts with the two-line SPDX and project header (copy it from any existing file). Python and shell scripts carry it as comments.
- `scripts/check-strings.py <derived-data>`: the string catalog must match the code, and every translatable string (app and package catalogs) needs all 13 non-English localizations (`zh-Hans`, `zh-Hant`, `ja`, `ko`, `ru`, `uk`, `de`, `fr`, `es`, `pt`, `id`, `th`, `vi`). The checker matches argument positions, multiplicity and types (including length modifiers), ignores literal `%%`, requires `other` in every plural/device variation (including nested sets), and checks every variation branch. Apple’s verbatim license text is exempt. `python3 -I scripts/check-strings.py --self-check` exercises the checker offline and runs in `scripts/test.sh`. Run with `--write` to add new strings to `Localizable.xcstrings`, then translate them.
- The crypt32 fix uses `scripts/build-crypt32-fix.sh` and the shared installer/checker with `--lock compat/crypt32-fix/toolchain.lock` (Steam defaults unchanged). The lock adds Bison; optional gettext is disabled. The script verifies the Wine archive/patches, strips debug data, clears the Wine builtin DOS marker for native prefix loading, fixes PE timestamps/build IDs and emits a deterministic ZIP. `crypt32-fix.yml` only runs manually and attaches the DLL ZIP plus Wine source to an owner-published draft release. Never run/publish it without instruction. The gated `Crypt32FixIntegrationTests` additionally needs `MACGACHA_CRYPT32_FIX_BUILD` pointing to a script output; it uses the synthetic upstream signature fixture to prove stock rejection/fixed acceptance while the runtime digest is unchanged.
- `python3 -I scripts/make-appcast.py --self-check` tests the one-item Sparkle feed, verbatim Markdown notes and their UTF-8/size/control-character validation, public-key validation and packaging build-number forwarding without network or real signing keys; it also runs in `scripts/test.sh`. `xcrun swift -warnings-as-errors scripts/verify-sparkle-signature.swift --self-check` uses public RFC 8032 vectors to check the native CryptoKit verifier; the signing step verifies every DMG against the public key embedded in the built app before creating the feed. Sparkle is pinned exactly to 2.10.0 in XcodeGen and linked only into the app. Test/preview models use an inert updater, and the live service refuses to start in Debug builds or XCTest hosts.
- `scripts/package-dmg.sh <release-name> [output-dir]`: builds Release and writes `MacGacha-<name>.dmg` (app plus an Applications link) and its `.sha256`. The numeric part of the name must match `MARKETING_VERSION` in `project.yml`; a suffix such as `-beta` only goes into file and tag names. Builds are ad-hoc signed until Developer ID signing lands. Ad-hoc builds have no Team ID, so the app carries `com.apple.security.cs.disable-library-validation` to load the embedded Sparkle.framework (hardened runtime stays on; the Rosetta helper has its own empty entitlements). Remove it once Developer ID signing gives the app and its frameworks one Team ID. `scripts/check-app-loads.sh <app>` signs a probe like the app and dlopens every embedded framework; `package-dmg.sh` and CI's Release job run it, because `codesign --verify` cannot see library-validation failures. `MACGACHA_BUILD_NUMBER` optionally supplies a positive integer for `CURRENT_PROJECT_VERSION` (default 1).
- `release.yml` (manual, `workflow_dispatch` on `main` with a `version` input such as `0.1.1-beta`) refuses an existing release or tag and a commit without green push CI, uses full checkout history and `git rev-list --count HEAD` as `CFBundleVersion`, rejects the placeholder `SPARKLE_PUBLIC_ED_KEY`, requires valid UTF-8 Markdown in `ReleaseNotes/<numeric version>.md` before building (for example `ReleaseNotes/0.1.3.md` for `0.1.3-beta`), runs `package-dmg.sh`, signs the DMG using the resolved Sparkle `bin/sign_update` and the step-scoped `SPARKLE_ED_PRIVATE_KEY` secret, embeds the version notes in a Markdown `description` inside a one-item `appcast.xml`, validates the XML, and creates a **draft** release `v<version>` with the DMG, its `.sha256` and `appcast.xml`. The update window and the initial draft body use the same version file. Editing the GitHub release body later does not change the update window. The owner publishes the draft. Never publish it yourself.
- The Steam shim has its own manual workflow (`steam-shim.yml`) and scripts (`build-steam-shim.sh`, `install-steam-shim-toolchain.py`). Its output must match `compat/steam-shim/SHA256SUMS` byte for byte.

## Code conventions

- Match the surrounding code: naming, comment density, file size. Comments explain *why*, not what.
- Tests use Swift Testing (`@Test`, `#expect`). New behavior comes with a test; bugs get a regression test first. Tests must be deterministic: no wall-clock pacing or sleeps that decide correctness. Use handshakes (`TestEvent`) and injected clocks and seams.
- **All file access goes through `ContainedFileSystem`.** Never build paths by string concatenation from untrusted input; use `SafeRelativePath`.
- Network access is limited to allowlisted HTTPS hosts (see `Sophon/DeliveryHostPolicy.swift` and the runtime manifest). Downloads are verified by size and SHA-256 before use.
- **User-visible text is localizable.** SwiftUI literals are automatic. Text built in code uses `String(localized:)` or `LocalizedStringResource` with format arguments, never concatenation. Sizes, dates and percentages go through formatters. Log and diagnostic text stays plain English. New strings ship with all 13 translations. Use HoYoverse's own terms from HoYoPlay in each language, for example the official Chinese 原神, 崩坏：星穹铁道, 绝区零, 开始游戏, 校验, 语音包. Ukrainian has no HoYoPlay reference, so follow the Russian and English HoYoPlay terms in Ukrainian wording.
- Errors shown to users go through `LauncherError` and `LauncherError+UserMessage.swift`, never raw payloads, URLs with tokens or paths with personal data.

## Product rules (hard requirements)

Code must keep these guarantees. A PR that weakens one won't be merged.

- **Game files are the user's data.**
  - Hide them only with non-replacing renames (`RENAME_EXCL`), recorded in the launch journal: "planned" before the rename, "done" after.
  - Never delete or overwrite a game file.
  - When unsure, keep the journal and report pending or conflict.
- **Prefixes must not link to the user’s home folders.** After wineboot and on every launch preparation, replace every shell-folder symlink (including internal links and Public profiles) with prefix-owned directories without inspecting its target; preserve real directories and their contents. Unsafe profile ancestors fail before Wine runs. Repair holds prefix/session exclusion and requires an empty process scan and an idle wineserver namespace keyed by the pinned prefix’s device/inode, so aliases and trailing slashes cannot bypass it; concurrent same-user writers outside Wine are outside the threat model for our owned prefix. Revision 2 migrates existing prefixes and persists in-prefix shell-folder registry paths.
- **Rosetta 2 is installed only by macOS’s own prompt with the user’s consent.** Probe with a short-deadline `arch -x86_64 true`; missing blocks Play and recommended setup, while unknown does not. A user request opens the embedded x86_64 helper through NSWorkspace, then checks activation and polls on an injected clock for at most five minutes. Never run `softwareupdate`, `sudo`, or pass `--agree-to-license`.
- **Interface language restart:** reserve the app before stopping a resumable game operation, join its consumer and pipeline lease, flush queued launch-settings writes, then save the final pending-plan identity. Launch-settings changes are refused while the restart reservation is held, including the relaunch handoff. Only a matching restart launch argument resumes that plan (or an interrupted verify with no plan). Game/recovery and non-resumable runtime work block restart. Failed relaunch keeps the current app usable and clears its continuation.
- **Sparkle updates:** macOS 27+ updates use the fixed GitHub latest-release appcast and Ed25519 signatures. Each release requires `ReleaseNotes/<numeric version>.md`. The update window shows its embedded Markdown as native formatted text, with a separate Version History link to the releases page. Later edits to the GitHub release body do not change the update window. Automatic checks follow Sparkle’s second-launch consent; no `SUEnableAutomaticChecks` override and no background downloading/installing. Installation/relaunch is postponed while startup, a launch slot (including recovery), a game operation or runtime/setup/import work is reserved, and resumes once via Observation after all reservations drain. The handoff then blocks new game/runtime operations until termination or a Sparkle abort, closing the asynchronous relaunch gap. A quit the user confirms (including Quit with a game running) still lets Sparkle install a prepared update: that is the same as replacing the app by hand, since games, downloads and recovery already survive a quit and reattach on the next start. Never start the updater in Debug builds or test hosts. The public key is the `SPARKLE_PUBLIC_ED_KEY` build setting (the release workflow rejects a placeholder); private signing keys are confined to the release signing step and never logged or stored in the repository.
- **Game display choice:** a connected-display probe supplies Wine's online, main-first monitor order on each Play, retaining sleeping displays and excluding only mirror followers (`CGDisplayMirrorsDisplay` is non-null). Missing NSScreen names never remove a display or shift its index. Pass Unity's plain `-monitor 1` explicitly by default, overriding Unity's remembered monitor; disconnected choices fall back to main without changing the saved UUID/name. An unavailable probe omits the argument. Jadeite receives its `--` default-launcher sentinel before trailing game arguments; the Steam shim forwards them directly. Reattachment never re-resolves display settings. Display names and UUIDs stay out of logs.
- **No `/etc/hosts` edits, no `sudo`, no system or security setting changes.** The Star Rail dispatch host is blocked by a per-session local proxy passed through `HTTP(S)_PROXY`.
- **No game data, game binaries or Apple D3DMetal/GPTK files in the repository or the app bundle.** D3DMetal is downloaded only after the user accepts Apple's terms, or imported from their own GPTK.
- **Star Rail 120 FPS:** off by default. When on, launch preparation rewrites only the `FPS` key of every existing `GraphicsSettings_Model_h*` JSON value in the prefix registry to 120, keeping other keys and the trailing NUL. When off, it writes 60 back only over a stored 120. It never creates the value: a missing or unreadable value launches normally and posts a `LaunchNote`. Only Global Star Rail offers or applies this setting; the CN registry key is unverified. Frame limits are Off, 30, 60, 90 or 120.
- **Anti-cheat workarounds** (jadeite, the Steam shim, the blocked host) are compatibility patches the user can turn off. Anything that injects code into the game process (FPS unlockers, mods) must be off by default and show a ban-risk warning before it's enabled.
- **Launched processes** get exactly the environment we build, a fresh process group, no inherited descriptors and default signal handling. Tests kill and reap every process they start.
- **Session supervision** belongs to `LaunchManager`, independently of event-stream consumers. Consumer cancellation detaches observation and leaves the game, proxy, locks and recovery supervised until verified end. Process-inspection uncertainty for plausible session processes (executable under the app Runtimes or snapshot install root, a recorded PID/start-time identity, or a live recorded spawned process group) keeps the proxy, journal and ownership in `recoveryPending`, with automatic retries on the injected clock. An unreadable process is foreign only with a readable executable path outside both roots and no live identity/group match; an unclassifiable path remains uncertain. Persisted group claims require the same boot plus the exact recorded leader PID/start-time identity or a verified surviving recorded member still in that group; a newer leader, launch-time lower bound or anonymous leaderless group confers no ownership. Only verified termination permits restore. A fully resolved conflict persists its recovery notice before deleting the resolved journal, preserves its recovery copy, and releases ownership. Completed restore snapshots retain a finalization checkpoint across unlink or directory-sync failure; retries sync even an absent journal before releasing ownership. Pending recovery notices survive restart until explicitly acknowledged; acknowledgment acquires session exclusion and waits for a durable resolved-journal removal barrier. Guards reserve recovery ownership across awaits and never restore while a watcher owns the session. Reattach uses persisted executable/log context and never recreates the session proxy or reads changed launch settings. Session-owned journal writes use their own atomic-temporary namespace so another game can download concurrently.
- **Game editions:** every Global and Mainland China edition has an independent game ID, record, prefix, settings, lock, journal and logs. Canonical install folder names do not follow the interface language: Global keeps its English folder names; CN uses `原神`, `崩坏星穹铁道`, `绝区零`. Adopt validates the executable and any `config.ini` / `game_version` edition and channel evidence before network access or record/plan mutation; only positive conflicting edition evidence or unsupported distributions (including Bilibili channel 14 / cps markers) cause edition refusal. Exact business keys in HoYoPlay uapc metadata count as edition evidence; sub_channel alone never identifies a distribution. Without edition evidence (including config-free Sophon installs), accept the selected edition and run normal verification. Semantic version numbers alone are not edition evidence; no reliable region-specific manifest samples are currently known for shared images. CN recipes have empty verified-build sets pending live verification. Region selection persists under `region`, defaults to Mainland China only for the Mac’s CN territory, and exposes three editions in rail order. Switching region never cancels operations or sessions; inactive regions keep local records and cached art without remote requests until selected.
- **Mutation barriers:** game operations recheck durable launch-journal absence after acquiring session exclusion, before reconciliation or mutation. Runtime publication/import/replacement and removal hold exclusive component pins through cleanup; any unresolved launch journal blocks runtime mutation, even if startup could not read it or rebuild its pins. Startup retains explicit unresolved games for app reservations, quit protection and guarded retries. A spawning journal with no identities receives the full confirmed-absence startup grace; prefix-matching helpers count as starting. Cross-volume conflicts use a contained, owner-only `.macgacha-recovery/<game>/<session>` beside the installation, journaled with directory identities before moving bytes; legacy failed cross-volume intents migrate only after verifying every hidden source remains owned.
- **Backdrop video:** native playback is silent and restricted to bounded VP9 Profile 0, 8-bit 4:2:0 WebM. Keep the still until the current source is `.playing` (first frame enqueued and layer ready). A failed or unavailable decoder leaves the still visible. Source replacement, pause and cleanup must not leak old callbacks or decoder work. No WebKit pages are generated or exposed by LauncherKit.
- **Session logs** can be disabled globally with `sessionLogsEnabled` in the root `launch-settings.json` (default true, separate from per-game settings). Callers pass that snapshot to log creation, proxy logging and diagnostics, and use `ProcessOutput.discard` for child stdout/stderr. Enabled sessions spawn with `SessionLog.processOutput`, never by reopening the log URL. `finish()` performs the final cap; `recover(at:)` verifies the ownership sidecar, caps stale output and resumes supervision. Retention removes only recorded inodes. Periodic truncation permits growth between ticks, and an exited launcher cannot cap a surviving child's output. Disabling session logs preserves existing logs, journals, prefix markers and file-recovery state; the launcher's path-free operational events remain enabled. Every `Launch failed` event and session `failed <stage>` line includes the shared error case and, when available, only an allowlisted errno symbol (numeric fallback) or process exit code; never free-form error descriptions, executable paths or stderr. Supervision only enqueues lifecycle/event lines and final caps; it never waits for their storage. Recovered logs are opened lazily on the log writer. A full queue drops the oldest pending items and counts drops. Verified end is checkpointed in the journal before enqueueing its at-most-once end line, including ends found while MacGacha was closed. The UI toggle lands with app integration.
- **Wine crypt32 fix:** CN Genshin/ZZZ on `d3dmetal-wine11.20-gptk4.0b3` require `crypt32-fix-wine-11.20-1`, independently of the game-patches toggle. This fixes Wine signature verification; no game is modified and nothing is injected. Verified prefix-only copies and a persisted native/builtin registry policy handle the runtime wrapper that removes environment overrides. The runtime stays read-only; session pins retain the component across reattach. Other editions/bundles are unchanged. Drop this workaround at Wine 11.21+. `runtimeSetupRequirements(for:)` includes the missing fix after the bundle, with manifest size and a localized name; `missingComponents` derives from the same requirements to block Play until setup completes.
- **New third-party components** in `runtime-manifest.json` need a pinned HTTPS URL, size, SHA-256 and license, with redistribution checked. Call them out in the PR description.

3. Don't commit build output, `MacGacha.xcodeproj`, `docs/`, `spike/`, secrets or downloaded binaries.
